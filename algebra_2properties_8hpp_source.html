1/// @file algebra/properties.hpp
2/// @brief Binding each law in the hierarchy to the runtime test that samples it.
3///
4/// The hierarchy itself is in `core/math/models.hpp` and has no dependencies, so anything
5/// in the library may name a law. The probes need random vectors and operator
6/// application, which live above the containers, so they are attached here by specializing
7/// `math::law_verifier`.
8///
9/// Two rules follow from the structure rather than from convention.
10///
11/// - A specialization tests **only its own law**. `verify_law` below walks the weaker
12/// laws by reading `L::base`. The walk is not written by hand at each level, so a
13/// probe cannot skip an intermediate law.
14/// - `math::law_verifier` is declared undefined in the hierarchy header. A law with no
15/// specialization here is a compile error the first time anything verifies it, so a
16/// law cannot be added without a test.
17///
18/// Sampling `⟨x, Ax⟩ > 0` over a basis and some random directions refutes a false claim
19/// cheaply and often. It never proves a true one. These probes reject; they do not
20/// certify. The claim remains the caller's.

34// -----------------------------------------------------------------------------
35// scalar and space laws
36// -----------------------------------------------------------------------------
37//
38// These are checked structurally rather than by sampling. The concept that admits a type
39// into the space hierarchy already requires the defining operations to exist and to be
40// callable with the right types, which is all a compiler can decide. The remaining
41// content, such as associativity, distributivity and the triangle inequality, is a
42// numerical property of a specific implementation. A probe for it would belong here and
43// none exists yet, so these verifiers are empty rather than misleading.
44
45#define NUM_STRUCTURAL_LAW(LAW) \
46 template <> \
47 struct law_verifier<LAW> { \
48 template <class Obj, class V> \
49 static void run(const Obj &, std::source_location) noexcept {} \
50 }

194/// @brief Verify `L` and every law it implies, weakest first.
195///
196/// The chain comes from `L::base`, so this is the only place the ordering is expressed.
197/// Adding a law between two existing ones makes every stronger law verify it with no edit
198/// to any verifier. This prevents the class of bug in which `spd` tested self-adjointness
199/// and definiteness but silently skipped semidefiniteness.
200///
201/// @tparam L The law to verify.
202/// @tparam Obj The object claiming it.
203/// @tparam V vec type the probes should draw from.
204template <class L, class Obj, class V>
205inline void verify_law(const Obj &object,
206 std::source_location loc = std::source_location::current()) {
207 if constexpr (!std::is_void_v<typename L::base>) {
208 verify_law<typename L::base, Obj, V>(object, loc);
209 }
210 law_verifier<L>::template run<Obj, V>(object, loc);
211}
