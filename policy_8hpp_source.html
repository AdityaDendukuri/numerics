1/// @file core/policy.hpp
2/// @brief Build capabilities and the one compile-time backend default.
3///
4/// A backend is a *substitution for a leaf kernel*, not a parameter threaded
5/// through every algorithm. BLAS replaces roughly six routines (dot, axpy, scal,
6/// nrm2, gemv, gemm); LAPACK replaces roughly six factorizations. Everything above
7/// them is pure algebra that merely calls those leaves.
8///
9/// Each backend is a plain namespace of free functions matching `num::kernel`'s
10/// signatures: `num::kernel` (the portable reference, always available, and the
11/// thing every other one funnels back into), `num::seq`, `num::omp`, `num::blas`,
12/// `num::cuda`. There is no tag or enum indirection between a caller and these:
13/// name the namespace you want. `num::accel` below is the single build-time
14/// default, so untagged call sites have something to resolve to.
15///
16/// A namespace is not a type, so an algorithm cannot be templated on which
17/// backend to call. Where one genuinely must run on more than one, it takes a
18/// `bool` (e.g. `template <bool Parallel = has_omp>`) and picks inside with
19/// `if constexpr`; where it must not, it just names a namespace.

78// Forward-declare every backend namespace so `accel` can name whichever is
79// available; each backend's own headers (include/<name>/*.hpp) reopen these
80// with real content. Reopening an empty namespace declaration is ordinary C++,
81// the same way num::kernel itself is built up across several headers.
82//
83// `num::seq` is the fallback when no accelerator was configured: `num::kernel`
84// itself cannot be `accel`'s target because it only knows raw pointers, not
85// `vec`/`mat` — `num::seq` (defined in container/vector_ops.hpp and
86// container/matrix_ops.hpp, where those types are visible) is the thin
87// container-aware wrapper around `num::kernel` that plays that role.
